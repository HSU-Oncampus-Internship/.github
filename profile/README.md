# 굿모니터링 (Good Monitoring)

지자체 캐릭터 IP를 무단으로 사용한 상품을 온라인 쇼핑몰에서 찾아내고, 담당자가 검토한 뒤 신고까지 이어 가도록 돕는 모니터링 플랫폼이다.
2026-2 AI/클라우드 온캠퍼스 인턴십 프로젝트로 진행했다. (2026.09.15 ~ 2026.11.17, 10주)

| 대상 캐릭터 | 기관 |
| --- | --- |
| 꿈돌이 | 대전광역시 |
| 해치 | 서울특별시 |
| 고양고양이 | 고양시 |

<br>

## 주요 기능

- **상품 수집**: 네이버 스마트스토어·쿠팡에서 캐릭터 상품과 판매자 사업자정보를 모은다. 쿠팡은 매일 오전 11시에 자동으로 수집한다.
- **의심 신호 탐지**: 승인 사업자 명단 대조와 가격 이상 규칙으로 검토가 필요한 상품을 골라낸다.
- **이미지 유사도**: 공식 캐릭터 이미지와 상품 이미지의 유사도를 계산해 판단 근거로 제공한다.
- **기관별 검토**: 지자체 담당자는 자기 기관의 상품만 보고, 정품·침해 여부를 직접 판정한다.
- **판매자 추적**: 사업자등록번호를 기준으로 플랫폼이 달라도 같은 판매자를 묶고, 다시 나타난 판매자를 추적한다.
- **신고 지원**: 검토가 끝난 상품의 URL과 근거를 모아 신고문 초안을 만든다.

<br>

## 시스템 구성

```text
 [네이버·쿠팡·테무·알리]
          │  수집 (Apify API / 수동 입력)
          ▼
 ┌─────────────────────┐      ┌─────────────────────┐
 │  AI-DATA            │      │  이미지 유사도 AI    │
 │  수집 · 탐지 · 신고  │      │  DINOv2 · FAISS     │
 │  MySQL (원본 DB)     │      │                     │
 └──────────┬──────────┘      └──────────┬──────────┘
            │ sync-ai-data (SELECT 전용)  │
            ▼                             ▼
 ┌──────────────────────────────────────────────────┐
 │  BE · Spring Boot 3.5 · Java 21 · MySQL          │
 │  인증 · 기관별 권한 · 검토 · 판매자 · 신고 API    │
 └──────────────────────┬───────────────────────────┘
                        │ REST API ({data, meta})
                        ▼
 ┌──────────────────────────────────────────────────┐
 │  FE · React · MUI                                │
 │  지자체 담당자 검토 화면 · 대시보드                │
 └──────────────────────────────────────────────────┘
```

BE는 AI-DATA DB를 직접 쓰지 않는다. 별도의 SELECT 전용 계정으로 원본을 조회한 뒤 BE 전용 DB에 매핑해 저장한다.

## 파트별 소개

### 1. 수집 · 탐지 · 신고 (AI-DATA `online-monitoring/`)

**채널별 수집 방식**

| 채널 | 방식 | 상태 |
| --- | --- | --- |
| 쿠팡 | Apify 유료 스크래핑 API로 검색 → 상세(판매자 사업자정보)까지 자동 수집, 매일 오전 11시 실행 | 운영 중 |
| 네이버 스마트스토어 | 입력 도구로 상품·판매자 정보를 직접 등록 | 운영 중 |
| 테무 · 알리익스프레스 | Apify로 상품 정보 수집, 상세(판매자 사업자정보) 수집 시도 중 | 확장 진행 중 |

**채널 선정 과정**

- **쿠팡**: Selenium, requests, Scrapling, Playwright(headless), AdsPower + Playwright를 모두 시도했지만 Akamai Bot Manager에 차단됐다. 그래서 Apify 수집기(`gio21/coupang-search-scraper`, `piotrv1001/coupang-product-details-scraper`)를 API로 호출하는 방식으로 바꿨다. 이 방식은 상품 정보뿐 아니라 상호명, 대표자명, 사업자등록번호, 통신판매업번호 같은 판매자 사업자정보도 함께 받아 온다.
- **네이버**: 자동 접근은 로그인 리다이렉트와 캡차에 막혔고, 쇼핑 검색 오픈API도 2026년 7월에 종료됐다. 그래서 수동 입력 도구(`product_manual_input.py`, `seller_manual_input.py`)를 만들어 입력 부담을 줄였다.

**처리 흐름**

```text
키워드 수집 → 판매자 자동 연결 → 미승인 사업자 탐지 → 가격 이상 탐지 → 검토 대상 목록 → 신고문 초안
```

| 단계 | 파일 | 내용 |
| --- | --- | --- |
| 수집 | `import_coupang_v2.py` | 쿠팡 검색·상세 수집. `--detail-new-only`로 새 상품만 상세 수집해 비용을 줄인다 |
| 판매자 구분 | `biz_type.py` | 사업자등록번호 가운데 2자리로 법인·개인을 판단한다 |
| 미승인 탐지 | `detect_unapproved.py` | 캐릭터별 승인 사업자 명단과 대조한다. 명단에 없으면 '미확인'으로 처리한다 |
| 가격 이상 | `price_anomaly_check.py` | 상품군 중위값, 공식 정가, 공식 판매처 동일 상품 등과 비교한다. 묶음 상품은 개당 가격으로 환산한다 |
| 검토 목록 | `list_flagged.py`, `report_flow.py` | 의심 상품을 URL과 함께 보여 주고, 사람이 직접 확인한다 |
| 신고문 | `make_report.py` | Gemini API로 신고문 초안을 쓴다. 상품 URL·상품명이 그대로 들어갔는지 검증하고, 실패하면 템플릿 문구를 대신 쓴다 |
| 자동 실행 | `run_daily.sh` | launchd로 매일 11시에 수집과 탐지를 이어서 실행한다. 네트워크 대기, 실패 시 1회 재시도, 단계별 로그 기록을 포함한다 |
| 검증 | `test_pipeline_logic.py` | MySQL 없이 SQLite로 탐지 로직을 검증한다 |

> 기관의 실제 승인 사업자 명단과 공식 정가표는 프로젝트 기간에 받을 수 없어 예시 데이터로 검증했다. 판정은 시스템이 하지 않고, 담당자가 근거를 보고 최종 판단한다.

### 2. 이미지 유사도 AI (AI-DATA)

공식 캐릭터 디자인 이미지를 기준으로, 수집한 상품 이미지와의 유사도를 계산한다.

- 사전학습 모델 DINOv2로 이미지 임베딩을 추출한다.
- FAISS로 공식 이미지와 가까운 상품 이미지를 검색한다.
- 결과 점수는 BE를 통해 검토 화면에 판단 근거로 표시된다.

### 3. 백엔드 (BE)

- Java 21 · Spring Boot 3.5 · Spring JDBC · MySQL 8. 로컬에서는 SQLite도 지원한다.
- API 명세 38개의 경로·요청·응답·오류·권한·인증 계약을 지킨다. 성공 응답은 `{data, meta}`, 오류는 `{error: {code, message, fields}, meta}` 형식이며 ID는 문자열이다.
- 세션 쿠키, CSRF 토큰, `Idempotency-Key`로 변경 요청을 보호하고, 기관(대전·고양·서울)별로 접근 범위를 나눈다.
- `sync-ai-data` 명령으로 AI-DATA 원본을 조회 전용으로 가져와 상품·판매자·신고 데이터로 매핑한다.
- Docker 기반 데모 DB 스크립트로 팀원 모두 같은 초기 데이터(꿈돌이 46건, 고양고양이 24건, 3개 기관 계정)를 각자 PC에 만들 수 있다.

자세한 실행 방법은 [BE README](https://github.com/HSU-Oncampus-Internship/BE)를 참고한다.

### 4. 프론트엔드 (FE)

- React · MUI로 지자체 담당자용 검토 화면과 대시보드를 만든다.
- 로그인 응답의 `csrfToken`과 `withCredentials: true`로 BE 세션 인증을 사용한다.
- 담당자는 의심 상품 목록에서 상품 URL과 근거(판매자, 가격, 이미지 유사도)를 보고 정품·침해 여부를 판정한다.
